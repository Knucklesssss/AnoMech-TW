判定輪廓只涵蓋共用傷害查詢；自訂塔、連線等判定不因此全部可視化。狀態測試驗證初始化順序及分支，不能取代遊戲中的原生效果驗證。

## 保留 A 的實作

- LiteNetLib 多人連線、確定性模擬、房主 AI、斷線接管及原有封包格式。
- 本地職業技能引擎、資源、讀條、冷卻與原生狀態同步。
- Moogle/Tuufless 策略、P3 轉場與 Hello World 的即時機制模型。
- 自訂隊伍列順序、既有外觀與動畫同步，以及現有場景選單與設定。
- 連續練習的死亡重試、成功換關及間隔行為。

同名檔案只合併需要的差異，沒有以 B 整份替換 A。

## 未採用及原因

| B 的項目 | 判斷 |
| --- | --- |
| Relay、隧道佇列、世界複製及其封包修補 | 依賴 B 的另一套多人架構；A 已有可測試的連線與同步，不替換核心 |
| 外觀、動畫、標記確認、AI 接管、自動名稱、平滑與 RTT 等 | A 已具備對應能力，不重複加入 B 的版本 |
| P2 TWLine 整套策略 | 與 A Tuufless 大部分重複，D3/D4 職業位置定義不同，保留 A 的配置 |
| P3 整套時序與歷史位置重寫 | 會替換 A 已有且有回歸測試的機制行為，保留原實作 |
| P4 歷史位置與整套失敗／易傷引擎 | 只採用相容時序，保留 A 的即時幾何與傷害規則 |
| 錄製／回放、任意位置編輯、NPC 收集器 | 需要 B 的錄製事件與生命週期，未直接移植 |
| 場景進度選擇框架 | P6 以兩個固定入口提供本次需要的練習起點，未新增整套框架 |
| 自動連勝、重試及連續關卡重寫 | 會改變 A 現有通關判斷與重試規則，保留 A 的行為 |
| 全套技能、坦克 LB 與錄製狀態規則 | 不替換 A 的職業技能引擎；只採用相容的初始化修正 |
| 原生狀態消失即取消模擬狀態 | A 由模擬引擎管理狀態生命週期；原生欄位短暫缺失不應清除模擬效果 |
| B 的區域還原、opcode 與原生相容閘門 | 與 B 的區域／事件生命週期耦合，不直接套用到 A |
| 場景預設可見性 | A 目前場景範圍無需複製 B 的篩選預設 |
| 常駐追蹤日誌的非同步管線 | A 使用不同且可選的日誌流程，沒有本次需要替換的依據 |

## 驗證

以下於本機執行通過：

- Release 建置：0 個警告、0 個錯誤。
- `Tests/AnoMech.P3.Tests.csproj`：含 P2、P3、P4、P5、P6 純邏輯、職業技能、UDP loopback 及多人確定性回歸。
- `Tests.PartyLayout/Tests.PartyLayout.csproj`：隊伍配置在狀態更新間維持，離開後還原。
- `Tests.Native/Tests.Native.csproj`：狀態建立順序、本地玩家取得效果、NPC 原生路徑與倒數。
- `tools/ClientData.Checks/ClientData.Checks.csproj`：技能文字、特性替換及資料比較。

`tools/NetTest` 是互動式連線工具，未啟動對外房間；自動化連線驗證由既有測試中的 loopback 覆蓋。尚未進入遊戲驗證畫面、原生 VFX 或真實跨機連線。

本地建置：`AnoMech/bin/Release/AnoMech.dll`。多人測試所有人必須使用相同建置。

1. 試跑兩個新增 P6 入口，檢查擊退、回場、宇宙天箭與限制解除後的 AI 路徑／時序。
2. 試跑 P4 及 P2 Standard，確認視覺與命中對齊。
3. 選擇 Omega 新策略，測試額外動力設定及漏接動力後的指派。
4. 切換精簡控制、判定範圍選項，確認啟動限制仍生效。
5. 檢查本地玩家狀態特效與 NPC 變身，並用相同建置進行多人測試。

等待上述實測後再決定發布；本次未建立 GitHub release。
