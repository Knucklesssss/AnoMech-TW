## 子專案 1 目標與範圍

做一支工具，讀本機繁中客戶端資料，為指定職業產出 90 級的技能資料清單，並與 xivapi 對應版本交叉核對。之後每個職業子專案都以這份清單寫規則。

不包含：任何職業規則、插件程式變更、發布、推送。

## 執行方式

- 新增 `tools/ClientData/`：獨立 C# 主控台程式（net9.0），不編進插件、不新增套件。直接引用 `C:/Users/Knuckles/AppData/Roaming/FFXIVSimpleLauncher/Dalamud/Injector/` 的 `Lumina.dll` 與 `Lumina.Excel.dll`（與插件建置同一個 API 13 路徑）。
- 用法：`dotnet run --project tools/ClientData -- <職業縮寫>`；可選參數：客戶端路徑（預設 `Z:/FINAL FANTASY XIV TC/game`）、等級（預設 90）、xivapi 版本、戰士標準答案檢查模式。
- 語言固定繁體中文，開啟資料表校驗碼檢查（不符即失敗）。客戶端版本讀自 `game/ffxivgame.ver`（目前 `2026.07.22.0000.0000`），寫入清單開頭。

## 資料怎麼挑

- **技能**：職業分類包含該職業、習得等級 ≤ 90 的技能；再經由技能替換表（ActionIndirection）、連段路線表（ActionComboRoute）與技能的連段前置欄位，補進不在熱鍵上的變化技能。不得只依「玩家技能」欄位過濾——變化技能可能未標示。
- **特性**：該職業、習得等級 ≤ 90 的所有特性。
- **狀態**：技能與特性說明文字引用到的狀態。同名多列（例如 PvE／PvP）全部列出並標為「需人工確認」，不自動擇一。
- **說明文字**：以 90 級、該職業條件求值（Lumina `ToMacroString` 取得巨集後求值），呈現實際威力、量譜數值與特性分支；無法求值的巨集保留原文並標記。
- **替換關係**：特性造成的技能升級（例如戰士 49 → 3549）要列在替換關係；若客戶端資料沒有直接關聯，工具必須把它列入「需人工確認」，不得省略。

## 輸出

每個職業一份 `docs/client-data/<職業縮寫>-90.md`，依序：

1. 客戶端版本、讀取時間、對應的 xivapi 國際服版本（或「未完成 xivapi 核對」）
2. 技能表：ID、名稱、類型、習得等級、詠唱時間、冷卻時間、冷卻組、額外冷卻組、充能數、消耗類型與數值、射程、效果範圍、可選目標（自身／隊友／敵人）、連段前置、替換關係。本規格所稱「冷卻組」「額外冷卻組」一律指 Action 資料表欄位值，不等於遊戲原生冷卻陣列索引（原生索引須以 `GetRecastGroup` 取得）
3. 特性表：ID、名稱、習得等級、說明（求值後）
4. 狀態表：ID、名稱、說明、是否需人工確認
5. 每個技能的完整說明（求值後）
6. 需人工確認清單
7. 與 xivapi 的差異表

`docs/` 在 `.gitignore` 內，清單以 `git add -f` 提交。

## xivapi 交叉核對

- 只比數值與 ID 欄位，不比文字（xivapi 只有日、英、德、法文）。
- 查詢方式已驗證：`https://v2.xivapi.com/api/sheet/Action?version=7.3&rows=31,37,42&fields=...` 支援指定版本與多列批次；不存在的版本回傳 400。
- 版本選擇：預設對 7.3、7.31、7.35、7.38、7.4 各比一次並列出各版本差異數，差異最少者記為對應國際服版本，列出該版本逐欄差異；可用參數指定單一版本。
- 以多列批次查詢減少請求數。

## 錯誤處理

- 找不到客戶端路徑、資料表校驗碼不符、職業縮寫不存在（列出可用縮寫）、該職業在 90 級查無技能：結束並說明原因，不產出清單，結束代碼非 0。
- 清單先寫暫存檔，完整後才取代正式檔；中途失敗不留半份清單。
- xivapi 連線或查詢失敗：仍產出清單，開頭標示「未完成 xivapi 核對」，並以與成功不同的結束代碼結束。此清單不得直接用於撰寫規則。
- 「需人工確認」項目不是錯誤，但必定列出。
